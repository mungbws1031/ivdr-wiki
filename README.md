# IVDR 인증 허브 (ivdr-wiki)

> **IVDR을 처음 접해도, 내 제품 한 줄 설명에서 시작해 인증 계획과 문서 초안까지 따라가며 배우는 허브**

- **배포:** https://mungbws1031.github.io/ivdr-wiki/
- **누구를 위해:** IVDR이 처음인 RA 담당자, IVDR을 잘 모르는 개발팀
- **구조:** 도구(`/auto/*`)가 중심이고, 가이드(인증 지도·개념 위키)는 도구 안에서 "이게 뭔데?"를 풀어 주는 설명으로 붙어 있다.

---

## 어디서 시작할까

### IVDR이 처음이면 → 지도와 위키부터
| 가고 싶은 곳 | 경로 | 얻는 것 |
|---|---|---|
| IVDR 여정 지도 | `/ivdr` | 5 페이즈 · 11 정거장으로 본 인증 전 과정, 정거장마다 "지금 할 일" |
| 개념 위키 | `/wiki` | IVDR 조항·부속서·표준·핵심 개념 설명. 본문의 용어를 누르면 여기로 연결된다 |

### 내 제품이 있으면 → 도구로
제품을 한 줄로 적고(`/auto/start`) 아래 흐름을 따라간다. 제품 정보 하나가 모든 단계를 움직인다.

```
제품 한 줄 ─▶ 등급 ─▶ 일정 ─▶ 실험계획 ─▶ 문서 초안 ─▶ 추적성
```

| 단계 | 경로 | 하는 일 |
|---|---|---|
| 제품 한 줄 · 일정 | `/auto/start` | 컨셉 한 줄로 스펙을 추정하고, 필요한 인증 요약과 인증 일정 로드맵(목표 판매일 → "늦어도 시작")을 보여 준다 |
| 제품 스펙 | `/auto` | 추정한 값을 확인·수정한다. "모름"으로 비워 둘 수 있다 |
| 등급 | `/auto/docs` | IVDR 클래스 추천(Rule 1~7 판정표), 필요 문서 세트, GSPR 1차 판정 |
| 국가별 판정 | `/auto/kr` · `/auto/us` · `/auto/transport` | 한국 MFDS, 미국 FDA, 운송·포장 |
| 실험계획 | `/auto/plan` · `/auto/results` | 결과 형태에 맞는 시험 목록·표본수, 결과 입력 |
| 문서 초안 | `/auto/overview` · `/auto/factory` · `/doc/:id` | 자동 채움 초안, 근거 원장, 변경 영향, Word·Markdown 내보내기 |
| 추적성 | `/auto/trace` | 요구사항 ↔ 위험 ↔ 검증 ↔ 증거 매트릭스, 설계 출력(BOM·PCB·SW 버전) 연결 |
| 시장성 점검 | `/auto/market` | 입력값으로 한 계산만 보여 준다 (판매 예측 아님) |

> 등급은 **추천**이고, 확정은 사람(RA)이 한다. 모든 초안은 **심사 제출 전 전문가 검토가 필요하다.**

## 그 밖의 기능 (그대로 유지)

### 인증 지도 4종
| 인증 | 규정 | 경로 |
|------|------|------|
| **IVDR** | Regulation (EU) 2017/746 — CE 마킹 | `/ivdr` |
| **ISO 13485** | ISO 13485:2016 — QMS 인증 | `/iso13485` |
| **IVDD** | 98/79/EC — IVDR 전환 대응 | `/ivdd` |
| **MDSAP** | 5개국(호주·브라질·캐나다·일본·미국) 단일 심사 | `/mdsap` |

공통 문서(QMS·설계·위험·성능/기술 증거)는 한 번 작성하면 여러 인증에 재사용된다.

### 문서 작성 워크스페이스 (`/doc/:id`, 문서 목록 `/documents`, `/write`)
문서마다 가이드 · 내용 소스 · 지침서 · 참고 문서 탭과 인라인 편집 템플릿을 준다. 입력은 브라우저에 자동 저장되고, 진척 바·완료 체크리스트로 진행도를 보여 준다.
- **MD 복사**, **완성본 .docx 받기**, **내 워드 템플릿 채우기**(회사 서식에 표시자를 넣어 올리면 자동 채움)

### 내장 계산기 5종
| 계산기 | 용도 | 쓰이는 문서 |
|--------|------|------|
| 민감도·특이도 | 2×2 혼동행렬 → Se/Sp + 95% CI | 성능평가·이익위험 |
| 검체수 산출 | 목표 성능·허용오차 → 최소 검체 수(Wilson) | 성능평가 |
| 검출한계(LoD) | 농도별 검출률 → LoD 추정 | 성능평가·분석성능 |
| 위험 매트릭스 | 발생확률 × 심각도 → 위험 등급 | 위험관리 |
| MKT(평균 동력학적 온도) | 운송·보관 온도 로그 → 실효 온도·라벨 범위 판정 | 운송 밸리데이션 |

### 기타
- **규제 역사** (`/history`) — 한국 의료기기 문서화 제도 60년 인포그래픽
- **일정 플래너** (`/schedule`) — 인증별 마일스톤 → 문서 페이지에 D-day로 반영
- **사전 준비 체크리스트** (`/prep-notes`) — 인증별로 미리 준비해 둘 자료
- **문구 라이브러리** — 자주 쓰는 규제 문구 + 내 문구 추가 + 구글 드라이브에서 가져오기

## 스택

- **React 19** + **Vite 6** + **TypeScript** + **Tailwind CSS v4**, 라우팅 `react-router-dom` 7 (라우트별 지연 로딩)
- 워드 내보내기: `docx` · `docxtemplater` · `pizzip` (사용할 때만 로드)
- 저장: 브라우저 `localStorage`만 쓴다. 서버로 보내지 않는다. 전체 백업 JSON 내보내기·가져오기 지원
- 개념 위키 원본: `content/wiki/*.md` (옵시디언 볼트) → 빌드 때 사이트로 변환

## 실행

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm test           # 단위 테스트 (vitest)
npm run build      # 타입체크(tsc -b) + 프로덕션 빌드
npm run preview    # 빌드 결과 미리보기
```

## 배포

`main`에 푸시하면 GitHub Actions(`.github/workflows/deploy.yml`)가 빌드 후 **GitHub Pages**에 배포한다. `vite.config.ts`의 `base`는 빌드 시 `/ivdr-wiki/`다.

## 폴더

| 위치 | 내용 |
|---|---|
| `src/` | 앱. `src/lib/`은 판정·계산 순수 함수, `src/components/auto/`는 도구 화면, `src/data/`는 지도·문서 템플릿 |
| `content/` | 개념 위키 원본(옵시디언 볼트). 사용법은 `content/README.md` |
| `public/`, `vite/`, `scripts/` | 정적 파일, 위키 변환 플러그인, 로컬 확인용 스크립트 |
| `docs/` | 제품 요구사항 `docs/PRD.md` |
| `docs/projects/` | 작업 묶음과 진행 상태 (`docs/projects/README.md`) |
| `docs/reviews/` | 사용성·검토 기록 |
| `experimental/server/` | 아직 배포하지 않은 AI 서버 초안 |
| `.claude/skills/` | 에이전트(Claude)용 부서 스킬 |

에이전트 작업 규칙은 `CLAUDE.md`에 있다.
