# 작업 묶음 (projects)

새 대화 하나에 묶음 하나를 맡긴다. 새 대화는 저장소의 `CLAUDE.md`(공통 규칙)를 자동으로 읽는다. 시작할 때 묶음의 `BRIEF.md`를 함께 읽게 한다.

**시작 문장 예:** `CLAUDE.md와 projects/01-traceability-2/BRIEF.md를 읽고, 계획부터 세워줘.`

전체 그림: [mindmap.html](mindmap.html) (브라우저로 열기) · [roadmap.xmind](roadmap.xmind) (XMind로 편집)

|---|---|---|---|---|
| 01 | [추적성 2단계](01-traceability-2/BRIEF.md) | 제품 기능 확장 | 완료 | 추적성 매트릭스(REQ↔RSK↔VFY↔EVD)에 설계 출력과 변경 영향, 리비전·감사 기록을 더한다. (설계 출력 DSO 등록·영향 후보 판정·CSV 감사 기록 완료) |

## 추천 순서
1. **바로 가능**
   - 01 추적성 2단계, 07 검증 3차, 06 사례 적용(완료), 09 화면 품질
   - 05·10은 사용자 방향이 정해지면 시작한다.
2. **사용자 준비 후**
   - 02 원문 대조: 네트워크 허용이 필요하다.
   - 03 AI 서버: Vercel·키 설정이 필요하다.
3. **03 다음**: 04 다중 사용자
4. **설계부터**: 08 MDR

## 규칙
- 묶음끼리 같은 파일을 동시에 크게 고치지 않는다(특히 `src/lib/trace.ts`, `src/data/spec/`).
- 동시에 진행하면 먼저 머지된 쪽을 다음 묶음이 받아서 시작한다.
- 묶음을 끝내면 `docs/PRD.md` 출시 이력과 이 표의 상태를 갱신한다.
