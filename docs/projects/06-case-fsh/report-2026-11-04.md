# 06 사례 적용: 갱년기 FSH — 사례 보고서 (2026-11-04)

> 가상 사례 점검이며 식약처·FDA의 공식 심사·자문이 아니다. 회사명·시장 수치는 사용자가 아직 주지 않아 전부 자리표시자([회사명 미입력] 등)로 둔다.

## 0. 방법

- 입력 컨셉 문장: "내 소변으로 갱년기 호르몬 변화를 모니터링하고 싶다. 집에서 쓰는 스틱만, 기기 없이, 눈으로 결과 확인. 유럽·한국·미국에 출시"
- 임시 vitest 파일(`.tmp/fsh-case.test.ts`, 확인 후 삭제)로 앱의 실제 코드 경로를 그대로 실행했다:
  `parseConcept` → `applyConcept` → `classify`(IVDR) → `classifyKr` → `classifyUs` → `evaluateDocSet` → `gsprChecklist` → `hazards`/`draftTokens` → `buildRoadmap`/`schedule`/`planStudies` → `marketCheck`.
- `rule1to3Flags`(감염병·혈액형·유전자 검사 등)는 컨셉 문장에 안 나와 있어서, 끝까지 돌리기 위해 전부 "아니오(false)"로 사람이 채웠다고 가정했다. 실제 사용자라면 이 질문에 직접 답해야 한다.
- 화면(UI)은 거치지 않았다 — `src/lib`의 판정·초안 함수만 직접 호출했다. 화면 단위 확인(버튼 동작 등)은 이번 보고서 범위 밖이다.

## 2. 판정 결과 (실제 실행값)

### IVDR (EU)
- **Class C**, status: recommended, Rule 4(a)
- 근거: "일반인 자가검사는 Rule 4(a)에 따라 C입니다. 임신·가임력·콜레스테롤 검사와 소변의 포도당·적혈구·백혈구·세균 검출이라면 예외로 B입니다." — FSH는 이 예외 목록에 못 들어가 일반 규칙(C)으로 떨어진다.
- 중요: 이 실행에서는 openQuestions가 비어 있어 status가 "recommended"로 나왔다(실제로는 FSH가 Rule 4(a) 예외 목록 원문에 있는지 아직 모르는 상태인데도 "확인 필요" 표시가 메시지에 안 붙는다 — F-11, docs/reviews/mfds-panel/2026-11-04-3차.md에서 이미 발견).
- 적합성 경로: Annex IX(QMS+기술문서 평가) 또는 Annex X+XI, 자가검사 기기 추가 평가(Annex IX 5.1)

### 한국 (MFDS)
- **등급 3 (추천, 잠정)**, 자가검사 확인(`selfTest.status = "check"`)
- 근거: "일반인 자가검사는 틀린 결과를 전문가가 걸러 주지 못해 3등급 후보예요."
- 자가검사 허용 품목: `KR_SELF_TEST_ITEMS`(hcg·glucose·covid·flu·drug) 목록에 FSH가 없어 "고시의 자가검사용 품목에 있는지 확인하지 못했습니다"로 정확히 보류됨.

### 미국 (FDA)
- **Class I**, 규정 21 CFR 862.1300, 제품 코드 "NGA (OTC) · CGJ", pathway: check (확인 필요)
- 근거: "Class I — 510(k) 면제지만 § 862.9 제한이 붙어요. 예전 가정용 폐경 FSH 소변 검사는 510(k)를 거친 사례가 있어요(K040575·K030058·K052662). 앱 알고리즘으로 폐경 '단계'를 판정하는 것처럼 새로운 용도·기술이면 면제 범위를 벗어날 수 있어서 862.9 원문으로 확인해야 해요."
- `US_KNOWN.FSH`에 2차 자료(FDA 제품 분류 DB·510(k) 사례, 확인일 2026-11-03)로 이미 반영돼 있던 특례 — 3국 중 가장 정교하다.
- CLIA: 가정용(OTC)이라 면제(waived) 분류.

### 필요 문서 (evaluateDocSet, 일부)
required로 떨어진 문서: intended-purpose, qualification-statement, classification-rationale, conformity-route-plan, device-description, design-manufacturing-info, tech-doc-toc-gspr, labelling-spec, ifu, benefit-risk, stability-study, dd-plan, design-inputs, design-outputs 등. sw-validation·cybersecurity는 "unknown"(스틱만·눈으로 읽기라 소프트웨어 없음 — 전체 목록은 `evaluateDocSet` 원시 출력 참고, 여기는 요약만 남김).

### GSPR 1차 판정
해당(applies) 14개, 비해당(na) 3개, 확인 필요(check) 3개 (20개 조항 중). 확인 필요 조항: §12(생물 유래 물질 포함 여부), §14(측정 기능 — result.kind 미입력), §16(소프트웨어 — 입력 칸 일부 비어 있어 확인 필요로 남음).

### 위해요인 (hazards, 9개)
R-001 위양성, R-002 위음성, R-003 간섭·교차반응, R-004 보관·운송 중 성능 저하, R-005 유효기간 경과 사용, R-006~008 사용 오류(채취·판독 시간·결과 해석), R-009 생물학적 위험(소변 취급). 전기·SW·채혈침 위해는 없음(스틱만·소변이라 당연).
- R-001·R-002의 harm 문구가 "'폐경 이행기(갱년기) 여부 확인 보조' 판단을 잘못 내림 — 위해 [검토 필요]"로, 구체적이지 않다 — 기존 F-12와 같은 원인.
- P(발생 가능성)·S(심각도) 칸은 전부 `[__]`로 비어 있다 — 수치를 지어내지 않았다.

### 시장성 (marketCheck)
- 규제 장벽: 점수 2(높음) — "EU Class C · KR 3등급" (미국은 Class I이지만 경로 확인 필요라 평균을 못 끌어올림)
- 출시 속도: 점수 3, 23~51개월 (로드맵 추정 범위, 목표 출시일 미입력)
- 증거 부담: 점수 3, 필수 실험 6개(교차반응·간섭 물질·실시간 안정성·사용적합성 형성/총괄 평가·임상 성능 일반인 사용 연구 포함)
- 판매 가능 지역: 점수 5, EU·한국·미국 3곳
- 경쟁·차별화, 가격 여지: **입력 없음 — 판정 불가** (회사명·시장 수치 모두 [회사명 미입력]/[확인 필요])
- 전체 헤드라인: "해볼 만한데, 챙길 게 있어요. 규제 장벽 높음(EU Class C · KR 3등급) · 출시까지 23~51개월. 시장 근거는 0/6만 들어 있어 '잘 팔릴지'는 아직 판단할 수 없어요."

## 3. 무엇이 자동으로 됐는가

- 문장 한 줄에서 분석물·검체·사용자·환경·시장을 키워드로 바로 뽑아 스펙을 채웠다.
- 3국(EU·KR·US) 등급·경로를 동시에 추천하고, 미국은 이미 FSH 전용 특례(21 CFR 862.1300)까지 반영돼 있었다.
- 필요 문서 목록, GSPR 20개 조항 1차 판정, 위해요인 9개, IFU·라벨 문구 초안, 실험계획까지 전부 빈칸 없이(수치는 제외) 바로 나왔다.
- 모르는 값(한국 자가검사 허용 품목, 미국 경로 확정 여부, GSPR §12·14·16)은 "확인 필요"로 정확히 보류했다 — 지어내지 않았다(앱의 기본 원칙이 잘 지켜짐).

## 4. 무엇을 사람이 해야 하는가

1. **IVDR Rule 4(a) 예외 목록 원문(Annex VIII) 확인**: FSH가 자가검사 예외 품목(B)에 포함되는지. 지금은 "C(원문 확인 필요)"지만 코드상 "확인 필요" 꼬리말이 안 붙어 있어 더 확정적으로 들린다(F-11).
2. **국내 고시 원문 확인**: FSH가 자가검사용 허용 품목에 있는지, 있다면 등급은 몇 등급인지. `KR_SELF_TEST_ITEMS`에 FSH를 추가할 근거가 되는 자료가 필요하다.
3. **미국 § 862.9 제한 원문 확인**: "앱 알고리즘으로 폐경 단계를 판정"하는 것이 면제 범위를 벗어나는 새로운 용도인지 FDA 제품 분류 DB·규정으로 직접 확인.
4. **rule1to3Flags 답변**: 이 사례에서는 임시로 전부 "아니오"로 가정했다 — 실제로는 사람이 직접 답해야 분류가 확정된다.
5. **GSPR §12·14·16 확인**: 원료 생물 유래 물질 여부, 결과 형태(정성/정량) 입력, 소프트웨어 유무 확정.
6. **P·S(위험 발생 가능성·심각도) 채우기**: 위험관리 팀이 회사 기준으로 매겨야 한다 — 앱은 지어내지 않는다.
7. **clinicalDecision 문구 확정**: 자동 채움 문구("폐경 이행기(갱년기) 여부 확인 보조")와 BRIEF 요구 안전 문구("진단 아님, 호르몬 변화 모니터링") 중 사람이 하나를 고르거나 다듬어야 한다 — `docs/projects/06-case-fsh/ifu-label-draft.md`, `issues.md`(F-14) 참고.
8. **시장 데이터 입력**: TAM/SAM·점유율·가격·경쟁 제품·차별점·타깃 고객. 지금은 전부 [회사명 미입력]/[확인 필요] 상태라 "잘 팔릴지" 판단이 아예 안 된다.

## 5. 앱에서 아쉬웠던 점 (요약 — 상세는 issues.md)

- **F-11(경미)**: FSH처럼 preset이 "other"인 자가검사는 분류 메시지에 "(원문 확인 필요)" 꼬리말이 안 붙어 단정적으로 들린다.
- **F-12(주요)**: "other" preset의 위해(harm) 문구가 `clinicalDecision` 문장을 그대로 따서 구체성이 떨어진다.
- **F-13(경미, 보고만)**: 미국은 FSH 전용 판정이 있는데 EU·KR은 일반 규칙만 있어 3국 판정의 정교함 차이가 크다.
- **F-14(신규, 주요)**: `concept.ts`의 `DECISION.other`가 채우는 clinicalDecision 문구("폐경 이행기(갱년기) 여부 확인 보조")가 BRIEF가 요구하는 안전 문구("진단 아님, 호르몬 변화 모니터링")와 다른데, 화면에서 둘이 다르다는 경고가 없다. — `docs/projects/06-case-fsh/issues.md` 참고.
- `src/data/spec/fields.ts`의 `market.target` placeholder("갱년기 증상이 시작된 30~40대 여성")는 앱이 보여 주는 입력창 예시 문구일 뿐 실제 조사값이 아니다 — 이 보고서에서 타깃 고객은 전부 [확인 필요]로 둔다.
