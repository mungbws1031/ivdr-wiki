# 사용자 관점 사용성 점검 — 3차 (2026-11-04)

2차 점검(10-30) 뒤에 새로 생긴 화면 — **시장성(`/auto/market`)**, **추적성 매트릭스(`/auto/trace`)**, **제품 기획의 개념 스케치(`/auto/start`의 `ConceptSketch`)** — 를 점검했다. 코드는 바꾸지 않았고, 개선안은 제안이다.

## 방법 — 이번 회차의 제약
- `npm run build`로 빌드하고 `python3 scripts/spa-server.py`로 `dist/`를 서빙했다(http://127.0.0.1:4199/ivdr-wiki/). `/`, `/auto/market`, `/auto/trace`, `/auto/start` 모두 200 응답을 확인했다.
- **이 환경(로컬 Windows 세션)에는 Chromium·Playwright가 설치돼 있지 않고, `npx playwright install`이 승인 정책으로 막혀 있다.** CLAUDE.md가 가정하는 클라우드 세션의 `/opt/node22` 경로도 없다. 그래서 2차처럼 실제 화면을 캡처해 픽셀 단위로 재지 못했다.
- 대신 **소스 코드 기반 점검**을 했다 — 해당 화면의 레이아웃 구조(그리드·플렉스), 인라인 스타일의 치수(`minHeight`, `minWidth`, `overflow-x-auto` 등), 가로 스크롤 처리, 용어·문구를 직접 읽었다. 실제 렌더링에서만 드러나는 문제(폰트 줄바꿈 위치, 실제 체감 속도 등)는 이번 점검으로 잡아내지 못했을 수 있다 — **다음 회차에서 Playwright가 설치된 환경으로 다시 확인해야 한다.**
- 페르소나는 2차와 동일하게 A(개발자, 규제 지식 없음)·B(RA 담당자)를 썼다.

## 확인한 것 (코드 기준)

### 시장성 (`src/components/auto/MarketPage.tsx`)
- 단계 탭(`AutoSteps`)의 "기획" 그룹에 "시장성"이 들어 있어(U-2 개편 구조에 맞음) 길을 잃을 염려는 적다.
- 맨 위에 "어때? 잘 팔릴 거 같아?" 질문형 제목과 캐릭터(Minimi) + 요약 문장이 먼저 오고, "판매 예측이 아니에요"를 두 번(본문 설명, 캡션) 명시한다 — CLAUDE.md 4번 규칙("시장성 점검은 판매 예측이 아니다")을 화면에서도 지킨다.
- 경쟁 제품 표는 `overflow-x-auto` + `minWidth: 860`으로 감싸 모바일에서 표만 가로 스크롤되고 페이지 전체 가로 넘침은 나지 않는 구조다(기존 표 패턴과 동일).
- 입력칸·버튼의 `minHeight`가 대부분 40px 이상이다(경쟁 제품 추가 버튼 40, 입력하기 링크 28~40 혼재).

### 추적성 매트릭스 (`src/components/auto/TracePage.tsx`)
- 상단 4개 타일(커버리지 %)이 `repeat(auto-fit, minmax(min(100%,200px),1fr))`로 모바일에서 1열로 떨어지게 되어 있다.
- 요구사항/위험 표 모두 `overflow-x-auto` + `minWidth: 900`·`860`으로 감싸 가로 스크롤이 표 안에서만 일어난다.
- "검토함" 버튼의 `minHeight`가 36px로, 다른 화면의 40px 기준(U-6 개선 기준)보다 조금 낮다.
- 연결 편집(`EditLinks`)의 삭제 버튼은 32×32px — U-6에서 세운 "최소 40px" 기준보다 작다.
- "검토 연결 편집" 영역의 `<select>`는 `maxWidth: "100%"`가 있어 모바일에서 넘치지 않게 막아뒀다.

### 개념 스케치 (`src/components/auto/ConceptSketch.tsx`, `/auto/start` 안)
- SVG는 `viewBox 0 0 960 620`에 `width:100%`·`minWidth:640`·`height:auto`로, 390px 화면에서는 가로 스크롤이 필요하다.
- 다만 모바일에서만 보이는 안내 문구("옆으로 밀면 스케치 전체가 보여요 →", `sm:hidden`)를 바로 아래 넣어서, U-3·U-6에서 지적한 "경고만 있고 안내가 없는" 패턴을 이번엔 미리 막아뒀다.
- 하단 캡션에 "개념 스케치 — 실제 디자인 아님 · 치수·시간은 설계·시험 후 확정"이 SVG 안에도, 화면 텍스트에도 중복으로 들어가 과신 방지는 잘 돼 있다.
- 색상 선택 칩은 `minHeight: 40`으로 U-6 기준을 만족한다.

## 잘된 점 (2차 개선이 새 화면에도 이어짐)
- 새 화면 3개 모두 표·SVG를 `overflow-x-auto`로 감싸 **페이지 전체 가로 넘침은 나지 않는다**(U-2~U-6 때 정한 패턴을 그대로 따름).
- 시장성 화면은 "판매 예측 아님"을 CLAUDE.md 규칙대로 화면에서도 두 번 밝힌다.
- 추적성 화면은 자동 연결을 "후보"라고 못 박고, 사람이 "검토함"을 눌러야 확정되게 해 C-05(사람 판단 우선) 원칙을 지킨다.
- 개념 스케치는 모바일 가로 스크롤을 숨기지 않고 안내 문구로 미리 알려준다.

## 개선안 (우선순위)
1. **(V-1) 추적성 표의 작은 버튼을 40px로 키운다** — "검토함" 버튼 `minHeight: 36→40`, 연결 삭제 버튼 `32×32→40×40`(아이콘 크기는 유지하고 패딩만 늘려도 됨).
2. **(V-3) 추적성 화면에 용어 풀이(`Term`)를 연결한다** — REQ·RSK·VFY 열 머리글과 범례에 한 줄 설명을 붙인다(이미 `glossary.ts`에 비슷한 용어가 있으면 재사용).
3. **(V-2) 개념 스케치의 최소 너비를 낮추거나, 모바일에서 핵심 부분만 보이는 축소 보기를 추가한다** — 당장 급하지 않음(안내 문구로 이미 완화됨).
4. **(V-4) 다음 회차에 Playwright가 설치된 환경(클라우드 세션 등)에서 이번 3개 화면을 다시 스크린샷으로 확인한다** — 09-ui-quality 묶음과 함께 진행하면 좋다.

1~2번이 비용 대비 효과가 가장 크다.
