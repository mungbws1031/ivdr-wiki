# PRD — 의료기기 인증 문서 자동작성 툴 (ivdr-wiki)

- 문서 상태: v1.0 · 2026-11-01 · 지금까지 만든 기능을 정리한 PRD (PR #1~#47 기준)
- 배포: https://mungbws1031.github.io/ivdr-wiki/
- 저장소: `mungbws1031/ivdr-wiki`

---

## 1. 배경과 문제

체외진단(IVD) 의료기기를 출시하려면 시장마다 인증이 다르고, 필요한 문서는 수십 개다. 대략 이렇게 된다.
- EU IVDR: 문서 76개 이상
- 한국 식약처, 미국 FDA는 각자 다른 요구사항

지금은 다음 세 가지가 어렵다.

1. **개발 전에 큰 그림이 없다.** 어떤 인증이 필요한지, 얼마나 걸리는지, 판매하려면 언제까지 무엇을 시작해야 하는지 개발이 끝날 즈음에야 알게 된다.
2. **문서가 개발을 따라가지 못한다.** 제품 사양이 바뀌면 여러 문서를 손으로 고쳐야 하고, 어디가 바뀌었는지 놓친다.
3. **규제 지식이 없는 사람은 시작조차 어렵다.** 등급 판정, 적합성 경로, GSPR, 위험관리를 처음부터 알아야 문서를 쓸 수 있다.

## 2. 목표

| 목표 | 성공 기준 |
|---|---|
| 컨셉 한 줄로 시작 | 대충 적은 제품 컨셉만으로 등급 추천·문서 세트·초안이 나온다 (클릭 2번) |
| 개발과 동시에 문서 작성 | 제품 스펙이 바뀌면 모든 문서의 자동 채움 칸이 바뀌고, 사람이 쓴 칸은 "재검토 필요"로 표시된다 |
| 사람이 할 일만 남김 | 앱이 정할 수 없는 결정·실험·서명만 모아 보여 준다 |
| 인증 일정의 큰 그림 | 목표 판매일에서 거꾸로 "늦어도 시작"과 가능·불가능을 계산한다 |
| 그럴듯하지만 틀린 문서 방지 | 지어낸 수치·조항 0건. 모르는 값은 "확인 필요"·`[____]`로 남긴다 |

## 3. 비목표

| 범위 밖 | 이유 |
|---|---|
| 제출용 완성 문서 | 시험 데이터와 RA 검토 없이는 불가. 이 툴은 "출발점"을 만든다 |
| 시험 결과 생성 | 허위 데이터 위험. 시험 계획까지만 만든다 |
| 등급 최종 확정 | 사람(RA)이 확정한다. 앱은 추천과 근거만 낸다 |
| 실사 디자인 이미지 | AI 서버 연결 전까지는 SVG 개념 스케치만 |
| 회사 자산 사용 | 사내 TPP·템플릿은 쓰지 않는다 (범용 툴) |

## 4. 사용자

| 페르소나 | 상황 | 바라는 것 |
|---|---|---|
| A — 개발자·기획자 | 규제 지식 없음, 컨셉만 있음 | 필요한 인증·기간·문서를 한 번에 알고 싶다 |
| B — RA 담당자 | 특정 문서를 빨리 써야 함 | 정거장별 문서 템플릿, 자동 채움, Word 내보내기 |
| C — 품질·검토자 | 문서가 믿을 만한지 확인 | 근거 원장, 가정·추정 표시, 변경 영향, 점검 보고서 |

## 5. 핵심 원칙

1. **하나의 제품 정보(단일 원본).** 제품 스펙 하나가 등급·문서 세트·실험계획·문서 초안·로드맵을 모두 움직인다.
2. **추천이고 사람이 확정한다.** IVDR 클래스, 국내 등급, FDA 제품 코드 모두 사람이 확정한 값이 우선한다.
3. **수치·조항을 지어내지 않는다.** 위험 P·S, 성능 값, 시험 조건, 비교 기기 번호는 빈칸으로 둔다. 확인하지 못한 조항에는 "원문 확인 필요"를 붙인다.
4. **근거를 남긴다.** 문서의 값마다 근거 태그(입력·규칙·가정·추정·누락)를 단다.
5. **사람이 쓴 초안은 절대 덮어쓰지 않는다.**
6. **보수적으로 가정한다.** 빈 칸은 요구사항이 더 많은 쪽으로 가정해 진행하고, "(가정)"을 표시한다. 가정으로 나온 등급은 확정할 수 없다.

## 7. 기능 요구사항

### 7.1 기획 — 컨셉 → 인증·기간·스케치 (`/auto/start`)
- **컨셉 한 줄 입력**: 키워드로 스펙을 추정한다. 추정한 값은 "(추정)"으로 표시하고, 비어 있는 칸만 채운다.
  - 추정 대상: 제품 형태, 검체, 분석물, 사용자·환경, 결과·판독, 검사 방식, 앱, 시장, 재질
  - 등급을 바꾸는 빈 칸은 최대 5개만 질문한다.
- **판매할 곳·품질 인증·개발 시작일·목표 판매일** 입력
- **필요한 인증 요약**: 국가별 등급·경로 한 줄과 상세 링크
- **인증 일정 로드맵** (`lib/roadmap.ts`)
  - 항목: 개발, 검증·시험, 품질 인증(이미 있는 인증은 제외), EU·KR·US 인증, 양산
  - 기간은 추정 범위(최소~최대 개월)이고, 사람이 직접 고친 기간이 우선한다.
  - 실시간 안정성은 스펙의 유효기간을 쓴다. 출시는 막지 않는 것으로 계산한다(가속 시험으로 잠정 유효기간).
  - 계산: 가장 빠른·늦은 출시일, "늦어도 시작", 가장 긴 경로(★), 가능·빠듯함·불가능(부족 개월 수)
- **개념 스케치**: 제품 형태·판독·검체·앱으로 그린 SVG 구성도. SVG·PNG로 내려받는다.

### 7.2 제품 스펙 (`/auto`)
- 필드 정의는 데이터로 관리한다(`data/spec/fields.ts`). 폼, 진행률, 미입력 목록, 검증이 모두 여기서 나온다.
- 주요 항목
  - 식별 정보, 제품 유형·형태·재질
  - 분석물: 종류는 LH·hCG·혈당·콜레스테롤·소변 일반·기타, 그 밖에 cut-off
  - 검체, 결과 형태·판독·검사 방식, 사용자·환경
  - 의도된 목적, Rule 1~3 판단 질문, 멸균, 소프트웨어
  - 시장·품질 인증, 국내 등급·FDA 제품 코드(사람이 확인한 값)
  - 보관·안정성, 구성품, 기준 방법, 목표 성능
- "모름" 토글로 값을 null로 둘 수 있다. 예시로 채우기, 백업 내보내기·가져오기를 지원한다.

### 7.3 판정
- **IVDR 클래스 추천** (`lib/rules/classify.ts`)
  - Annex VIII Rule 1~7을 적용한다.
  - 자가검사 Rule 4(a) 예외(임신·가임력·혈당·콜레스테롤·소변 일반)는 B다.
  - 감염병은 담당자 판단으로 둔다.
  - 미답 항목이 있으면 잠정이다.
  - 사람이 확정하고, 스펙이 바뀌면 재확인을 요구한다.
- **Rule 1~7 판정표**: 규칙마다 해당·비해당·답변 필요와 이유. Rule 6은 Rule 1~5가 비해당일 때만 적용한다.
- **필요 문서 세트**(`applicability.ts`): 문서마다 필수·권장·선택·불필요·확인 필요와 이유를 단다.
- **GSPR(Annex I) 1차 판정**: 20개 조항을 장별로 해당·비해당·확인 필요로 판정하고, 근거 문서를 연결한다.
- **한국 MFDS** (`lib/kr`)
  - 등급 추천(잠정, 품목 분류 확인 전제)과 신고·인증·허가 경로
  - 자가검사 허용 품목 판정(2026-06 고시 개정 기준)
  - 국내 제출 자료와 재사용할 IVDR 문서
  - 한국 기술문서 초안
- **미국 FDA** (`lib/us`)
  - 확인한 품목: hCG 21 CFR 862.1155 Class II 510(k), LH 862.1485 Class I
  - 위험 특성으로 경로 추정, CLIA 판정, 제출 자료 16개, 510(k) 초안
- **운송·포장** (`lib/transport`): 적용 규격, PPWR 포장 요건, 시험 순서, 운송 과정

### 7.4 실험 (`lib/planner`, `/auto/plan`, `/auto/results`)
- 결과 형태(정성·정량)에 따른 시험 목록을 만든다.
  - 정성: CLSI EP12
  - 정량: EP05·EP06·EP09·EP17
  - 공통: 간섭, 교차반응, 안정성, 사용적합성
- 표본수를 계산한다. 목표 성능이 없으면 판정 기준을 만들지 않는다.
- 결과를 입력하면 해당 문서에 자동 반영되고, 입력 전에는 `[실험 후 입력]`이다.

### 7.5 문서 (`/auto/overview`, `/doc/:id`)
- 토큰 기반 자동 채움(`lib/tokens.ts`): 템플릿의 `{{auto.key}}`를 스펙·판정·실험 결과로 채운다. 값이 없으면 `[이름 — 스펙 미입력]`이다.
- **P1 초안**(`lib/drafts`)
  - 작동 원리
  - 라벨 심볼(ISO 15223-1 이름만)·경고
  - IFU 사용 단계·판독 기준·한계·경고
  - 위해요인 표(P·S는 빈칸), GSPR↔위험 추적표, 사용적합성 연계
- **근거 원장**: 문서별 입력·규칙·가정·추정·누락 수와 근거 확정 %
- **난이도 얼굴**: 문서와 전체 인증 난이도를 동물 캐릭터 표정으로 보여 준다(쉬움 → 비명).
- **변경 영향**: 문서를 처음 연 시점을 기준으로 바뀐 값과 영향받는 섹션을 표시한다. 사람이 쓴 섹션은 "재검토 필요"로 표시한다.
- **내보내기**: Word(.docx), Markdown, sug-doc-pipeline 형식 zip(초안 docx + state.json + input.json)
- **문서 공장**: 문서를 직원 캐릭터로 나타낸 대시보드. 미니룸·3D 건물·건물 단면 보기, 목표 체크리스트

### 7.6 검증 도구
- 부서별 Claude 스킬 7개(`skills/ivdr-*`)
- **가상 심사관 5인 패널 스킬**(`skills/mfds-review-panel`)
  - 체크리스트 51개, 시험 제품 6개, 보고서 양식
  - 1차 점검은 "사용 보류"(치명 1)였고, 수정 후 2차 점검은 "사용 가능 — 참고용"(치명 0·주요 0)
- **사용성 점검**(`reviews/ux-2026-10-30.md`): 문제 10개 중 1~3번 조치 완료

## 11. 남은 과제 (우선순위)

1. **규정 원문 대조**: IVDR Rule 4(a) 예외, 국내 자가검사 허용 품목·품목 등급, 21 CFR 862.9·862.1345, ISO 15223-1 심볼 명칭
   - 세션 네트워크에서 eur-lex.europa.eu, law.go.kr, mfds.go.kr, ecfr.gov를 허용해야 한다.
2. **RA 전문가 검토**: 규칙 검토자·날짜를 채운다. 기획서상 P1 통과 기준(RA 경력자 1명 이상 리뷰)이다.
3. **사용성 개선 4~10**
   - 결과 한눈에 맨 위 "지금 할 일 3개"
   - 문서 화면에서 바로 쓰기
   - 터치 대상 40px
   - 용어 풀이
   - 입력 현황판
   - 머리 링크
   - 저장 안내
4. **패널 부분 항목**: 추적성 매트릭스 자동 연결, IFU 일반인용 원리 문장, 분석물 종류 변경 시 임상 판단 재확인 경고
5. **AI 서버(Vercel)**: 문장 다듬기·번역·실사 디자인 이미지. API 키는 사용자가 Vercel에서 설정한다.
6. **P2 나머지**: MDR(비IVD 의료기기), 설계 엔진과 제품 프로파일 공유
7. **사무실(문서 공장) 디자인 개편**: 요즘 스타일 사무실과 직원 캐릭터

## 12. 위험과 대응

| 위험 | 대응 |
|---|---|
| 그럴듯하지만 틀린 규제 문서 | 규칙 데이터에서만 판정, 조항 번호는 확인한 것만, 모든 출력에 "검토 전 초안"·"원문 확인 필요" |
| 애매한 등급을 낮게 판정 | 보수적 가정, 감염병 등은 담당자 판단 보류, 가정으로 나온 등급은 확정 불가 |
