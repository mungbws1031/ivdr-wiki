# 3F 생산팀 (강아지 직원들)

IVDR 문서 공장의 **3F 생산** 부서다. 담당 분야는 공정·포장·운송·제조 기록이다. 이 부서 직원(문서) 7명이 하는 일을 이 스킬 하나로 수행한다. 문서마다 섹션 순서와 근거는 `references/documents.md`에 있다.

## 일하는 순서

1. **운송 경로를 정한다.** 목적지, 운송 방식(택배·항공·육상), 출하 박스 크기와 무게, 보관 온도, 위험물 여부를 스펙(`transport`)에서 가져온다.
2. **적용 규격을 판정한다.**
   - 택배이고 70 kg 이하면 ISTA 3A를 기본으로 하고, ASTM D4169를 대안으로 둔다. 70 kg를 넘으면 팔레트 화물이라 범위 밖으로 안내한다.
   - 항공 운송이 포함되면 저압 시험이 필수다.
   - 냉장(최고 8℃ 이하)이면 열 운송 시험을 넣는다.
   - 멸균 제품이면 ISO 11607을 적용한다.
   - 위험물이 '예'면 IATA DGR(항공)·ADR(육상)을 적용하고, '모름'이면 SDS 분류 확인을 요청한다.
3. **시험 순서를 쓴다.** 대기 조건 → 낙하 → 랜덤 진동 → 저압(항공 시) → 최종 낙하 → 온도 노출 → 판정 순서다.
   - 낙하 높이, 진동 강도, 박스 수는 `[ISTA 3A 원문 기준]`으로 둔다.
   - 판정은 포장 손상·누액 외관 검사와 운송 시료 대 비운송 대조의 성능 동등성으로 한다.
4. **EU 포장규정(PPWR)을 점검한다.** 포장 최소화, 빈 공간 비율, 재활용 설계, 재생원료, 라벨 항목을 확인한다.
   - IVD 접촉 민감 1차 포장만 일부 예외이고, 2·3차 포장은 예외가 아니다.
   - 적용 시점이 자료마다 다르므로 모든 항목에 **원문 확인 필요**를 붙인다.
5. **넘기기:** 운송 후 성능 비교 시험은 4F, 운송 위험은 5F 위험관리, 판정과 서명은 7F로 넘긴다.

## 담당 문서 (7개)

| 문서 | id | 필요 여부 | 근거 |
|---|---|---|---|
| 공정 밸리데이션 (IQ/OQ/PQ) | `process-validation` | 필수 | ISO 13485 7.5.6 |
| 멸균 밸리데이션 | `sterilization-validation` | 해당 시 | ISO 11135, ISO 11137 |
| 기기 마스터 기록 (DMR) | `dmr` | 필수 | ISO 13485 4.2.3 |
| 기기 이력 기록 (DHR/배치기록) | `dhr` | 필수 | ISO 13485 7.5.1 |
| 포장·멸균배리어 밸리데이션 (ISO 11607) | `packaging-validation` | 해당 시 | ISO 11607-1, ISO 11607-2 |
| 취급·보관·포장·배송 관리 | `product-preservation` | 필수 | ISO 13485 7.5.11 |
| 운송(수송) 밸리데이션 (ISTA 3A) | `transport-validation` | 해당 시 | ISTA 3A |

필요 여부가 '조건부·해당 시'인 문서는 제품 스펙으로 판정한다. 앱의 `/auto/docs`와 같은 규칙을 따르며, 판정할 수 없으면 "확인 필요"로 두고 7F로 넘긴다.

## 공통 원칙 (모든 부서 스킬 공통)

1. **수치를 지어내지 않는다.** 실험 결과, 합격 기준, 표본 수, 규격 원문 수치는 절대 만들지 않는다.
   - 실험 결과가 들어갈 칸은 `[실험 후 입력]`으로 남긴다.
   - 사람이 정해야 하는 사양은 `[사양: … — 사람이 정함]`으로 남긴다. 예: `[사양: 목표 특이도 % — 사람이 정함]`.
   - 유료 규격 원문에만 있는 값은 `[… 원문 기준]`으로 남긴다. 예: `[ISTA 3A 원문 기준]`.
2. **확인하지 않은 규제 사실에는 "원문 확인 필요"를 붙인다.** 조항은 조·부속서 단위로만 인용한다. 예: `IVDR Art.48`, `Annex IX`. 세부 항 번호를 짐작해서 쓰지 않는다.
3. **추천과 결정을 구분한다.** 클래스, 문서 필요 여부, 합격 판정, 서명은 사람이 결정한다. 이 스킬은 근거와 선택지를 정리한 뒤 결정을 **7F 결재실**(`ivdr-approval`)로 넘긴다.
4. **사람이 쓴 초안은 덮어쓰지 않는다.** 이미 작성된 섹션이 있으면 고칠 점을 "제안"으로만 따로 쓴다.
5. **섹션 순서를 지킨다.** 문서마다 정해진 섹션 순서(`references/documents.md`)를 따른다. 새 섹션은 맨 뒤에만 붙인다. 앱의 초안이 섹션 번호로 저장되기 때문이다.
6. **모르는 입력은 묻는다.** 제품 스펙이 비어 있으면 추측하지 말고 **1F 접수**(`ivdr-intake`)의 질문으로 채우도록 안내한다.
7. **한국어로 쓰고, 해외 제출본은 따로 만든다.** 규제 용어는 표준 영문을 괄호로 함께 적는다. 예: 의도된 목적(intended purpose).

## 앱과 함께 쓰기

이 스킬은 IVDR 위키 앱(https://mungbws1031.github.io/ivdr-wiki/)의 **문서 공장**에서 한 부서를 맡는다. 앱의 다음 화면과 같은 기준을 쓴다.
- 제품 스펙: `/auto`
- 분류·문서 세트: `/auto/docs`
- 운송·포장: `/auto/transport`
- 실험계획: `/auto/plan`
- 결과 입력: `/auto/results`
- 문서 작성: `/doc/<문서 id>`

사용자가 앱 백업 JSON(`app: "ivdr-wiki"`)을 주면 그 안의 `items["ivdr-spec-v1"]`(제품 스펙 JSON 문자열)을 입력으로 쓴다.

## 끝내기 전 점검

- [ ] 지어낸 수치가 없다. 실험·사양·규격 원문 값은 모두 자리표시로 남겼다.
- [ ] 확인하지 않은 규제 사실에 "원문 확인 필요"를 붙였다.
- [ ] 섹션 순서가 `references/documents.md`와 같다.
- [ ] 사람이 결정할 것(클래스·합격 판정·서명·회사 정보)을 목록으로 정리해 7F로 넘겼다.
- [ ] 다른 부서로 넘길 칸을 표시했다.
