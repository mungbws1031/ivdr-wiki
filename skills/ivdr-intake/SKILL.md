# 1F 접수 (제품 스펙 받기)

모든 부서는 제품 스펙에서 출발한다. 접수는 스펙을 빠짐없이, **추측 없이** 받는다.

## 일하는 순서

1. **첫 질문은 항상 "어떤 인증을 받아야 하나요?"다.** 한국 MFDS, EU IVDR, 미국 FDA 등 받을 인증과 품질 인증(KGMP·ISO 13485·MDSAP)부터 묻는다.
2. **`references/spec-fields.md`의 섹션 순서대로 묻는다.** 한 번에 한 섹션씩, 선택지가 있으면 선택지를 보여준다.
3. **모르면 비워 둔다.** "모름·나중에"는 `null`로 둔다. 비운 항목은 사람 할 일 목록에 남긴다.
4. **분류 판단 질문(Rule 1~3)은 예·아니오·모름으로만 받는다.** 감염병, 혈액형·조직형, 유전자, 암 선별, 동반진단, 선천성 선별, 생명위협이 해당한다.
5. **정리해서 확인받는다.** 입력한 값으로 의도된 목적 문장을 조립해 보여준다. 빈 요소는 `[검체 미입력]`처럼 표시한다.
6. **앱으로 넘긴다.** 아래 형식의 JSON 파일을 만들면 앱 `/auto` 화면의 '가져오기'로 불러올 수 있다.

```json
{"app": "ivdr-wiki", "v": 1, "kind": "spec", "exportedAt": "<ISO 시각>",
  "items": {"ivdr-spec-v1": "<ProductSpec JSON을 문자열로>"}}
```

ProductSpec의 필드 경로는 `references/spec-fields.md`의 '경로' 열과 같다. 최상위에 `"schemaVersion": 1`을 넣는다. 형식이 확실하지 않으면 앱 `/auto`에서 '스펙만 내보내기'로 받은 파일을 견본으로 쓴다.

7. **다음 부서를 안내한다.** 분류·문서 세트는 6F, 실험계획은 4F, 운송 정보는 3F로 넘긴다.

## 공통 원칙 (모든 부서 스킬 공통)

1. **수치를 지어내지 않는다.** 실험 결과, 합격 기준, 표본 수, 규격 원문 수치는 절대 만들지 않는다.
   - 실험 결과가 들어갈 칸은 `[실험 후 입력]`으로 남긴다.
   - 사람이 정해야 하는 사양은 `[사양: … — 사람이 정함]`으로 남긴다. 예: `[사양: 목표 특이도 % — 사람이 정함]`.
   - 유료 규격 원문에만 있는 값은 `[… 원문 기준]`으로 남긴다. 예: `[ISTA 3A 원문 기준]`.
2. **확인하지 않은 규제 사실에는 "원문 확인 필요"를 붙인다.** 조항은 조·부속서 단위로만 인용한다. 예: `IVDR Art.48`, `Annex IX`. 세부 항 번호를 짐작해서 쓰지 않는다.
3. **추천과 결정을 구분한다.** 클래스, 문서 필요 여부, 합격 판정, 서명은 사람이 결정한다. 이 스킬은 근거와 선택지를 정리한 뒤 결정을 **7F 결재실**(`ivdr-approval`)로 넘긴다.
4. **사람이 쓴 초안은 덮어쓰지 않는다.** 이미 작성된 섹션이 있으면 고칠 점을 "제안"으로만 따로 쓴다.
5. **섹션 순서를 지킨다.** 문서마다 정해진 섹션 순서(`references/documents.md`)를 따른다. 새 섹션은 맨 뒤에만 붙인다. 앱의 초안이 섹션 번호로 저장되기 때문이다.
6. **모르는 입력은 묻는다.** 제품 스펙이 비어 있으면 추측하지 말고 **1F 접수**(`ivdr-intake`)의 질문으로 채우도록 안내한다.
7. **한국어로 쓰고, 해외 제출본은 따로 만든다.** 규제 용어는 표준 영문을 괄호로 함께 적는다. 예: 의도된 목적(intended purpose).

## 앱과 함께 쓰기

이 스킬은 IVDR 위키 앱(https://mungbws1031.github.io/ivdr-wiki/)의 **문서 공장**에서 한 부서를 맡는다. 앱의 다음 화면과 같은 기준을 쓴다.
- 제품 스펙: `/auto`
- 분류·문서 세트: `/auto/docs`
- 운송·포장: `/auto/transport`
- 실험계획: `/auto/plan`
- 결과 입력: `/auto/results`
- 문서 작성: `/doc/<문서 id>`

사용자가 앱 백업 JSON(`app: "ivdr-wiki"`)을 주면 그 안의 `items["ivdr-spec-v1"]`(제품 스펙 JSON 문자열)을 입력으로 쓴다.

## 끝내기 전 점검

- [ ] 인증 질문을 가장 먼저 했다.
- [ ] 모르는 값을 채워 넣지 않았다 (`null`).
- [ ] 비운 항목 목록을 사용자에게 보여주었다.
