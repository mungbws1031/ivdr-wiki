# 5F 개발·설계 — 담당 문서 상세

앱의 문서 템플릿(`src/data/documents.ts`)과 문서 트리(`src/data/docTree.ts`)에서 자동으로 만든 목록이다. 섹션 순서를 바꾸지 않는다.

## 기술문서 (Annex II)
근거: Annex II

### 기기 설명서·사양 (`device-description`)

- 필요 여부: 필수
- 근거 조항: Annex II 1.1
- 앱에서 열기: `/doc/device-description` (전용 상세 템플릿)
- 왜 쓰는가: 심사자·당국이 '이 기기가 무엇인가'를 정확히 이해해야 나머지 증거를 평가할 수 있다. 기기를 명확·일관되게 기술해 오해와 추가 질의를 줄인다.
- 작성 전 준비물: 제품 외관·구성품 사진; 기술 사양(시약·하드웨어·SW 버전); 부품/구성 목록(BOM)
- 알아야 할 것: 기기 구성·작동 원리; 변형(variant)·모델 범위; 이전 세대·유사 기기와의 차이
- 섹션 순서:
  1. 1. 제품 식별
  2. 2. 기기 설명 및 의도된 목적
  3. 3. 구성 및 부품 목록
  4. 4. 기술 사양
  5. 5. 이전 세대·유사 기기

### 설계·제조 정보 (`design-manufacturing-info`)

- 필요 여부: 필수
- 근거 조항: Annex II 3
- 앱에서 열기: `/doc/design-manufacturing-info` (기본 템플릿)
- 왜 쓰는가: 안전·성능이 설계·제조 과정에서 어떻게 보장되는지 추적 가능해야 한다. 재현 가능한 품질을 입증해 제품 일관성과 책임 소재를 명확히 한다.
- 작성 전 준비물: 설계 도면·공정 흐름도; 제조 공정·설비 사진; 공정 파라미터·관리 기준값
- 알아야 할 것: 핵심 설계 입력·출력; 제조 공정의 중요 관리점(CTQ); 외주 vs 자가 제조 구분
- 섹션 순서:
  1. 1. 목적 · 적용 범위
  2. 2. 핵심 내용
  3. 3. 근거 · 참조
  4. 4. 검토 · 승인

### 기술문서 목차 + GSPR 체크리스트 (`tech-doc-toc-gspr`)

- 필요 여부: 필수
- 근거 조항: Annex II, Annex I
- 앱에서 열기: `/doc/tech-doc-toc-gspr` (전용 상세 템플릿)
- 왜 쓰는가: GSPR은 모든 IVD가 지켜야 할 안전·성능 요구의 목록이다. 각 요구에 증거를 매핑하는 것은 적합성을 빠짐없이·추적 가능하게 입증하는 뼈대를 만들기 위함이다.
- 작성 전 준비물: 위험관리 파일·성능평가 보고서; GSPR 각 항목 대응 증거 목록·위치
- 알아야 할 것: Annex I GSPR 각 항목의 의미; 내 기기에 적용/비적용되는 요구 구분; 충족 증거가 어디에 있는지(추적성)
- 섹션 순서:
  1. 1. 기술문서 목차 (Annex II)
  2. 2. 시판 후 기술문서 (Annex III)
  3. 3. GSPR 체크리스트 (Annex I)

### 라벨 사양서 (`labelling-spec`)

- 필요 여부: 필수 — UDI 캐리어·CE·NB 번호 포함.
- 근거 조항: Annex I (정보), Art.18
- 앱에서 열기: `/doc/labelling-spec` (전용 상세 템플릿)
- 왜 쓰는가: 사용자는 라벨·IFU만 보고 기기를 쓴다. 정확한 정보 표기는 오용으로 인한 환자 위해를 막고 법적 정보 제공 의무를 충족하기 위함이다.
- 작성 전 준비물: 현재 라벨 시안·목업; UDI-DI·제조자 정보·보관조건·유효기간; 심볼 표준(ISO 15223-1) 적용표
- 알아야 할 것: IVDR이 요구하는 필수 라벨 정보 항목; UDI 캐리어·CE·NB 번호 표기 규칙; 적용 심볼 표준(ISO 15223-1)
- 섹션 순서:
  1. 1. 제조자·연락처
  2. 2. 기기 식별 정보
  3. 3. 성능·용도 표시
  4. 4. CE 마킹 및 NB
  5. 5. 언어

### 사용설명서(IFU) (`ifu`)

- 필요 여부: 필수 — 자가검사는 사용적합성 검증과 연계.
- 근거 조항: Annex I (정보)
- 앱에서 열기: `/doc/ifu` (전용 상세 템플릿)
- 왜 쓰는가: 특히 비전문가 사용 시 잘못된 사용은 곧 오진으로 이어진다. 명확한 사용설명은 사용 오류 위험을 통제하는 핵심 안전장치다.
- 작성 전 준비물: 사용 절차 초안·위험관리(사용오류); 사용 단계별 일러스트/사진; 사용적합성 검증 결과(자가검사 시)
- 알아야 할 것: 사용자 수준(전문가/비전문가)에 맞는 표현; 사용 단계별 위험과 경고; 언어·형식 요건
- 섹션 순서:
  1. 1. 기기 식별 및 제조자
  2. 2. 의도된 목적 및 적응증
  3. 3. 검사 원리
  4. 4. 사용 방법 (단계별)
  5. 5. 성능 특성 요약
  6. 6. 한계·주의·경고
  7. 7. 심볼 범례

### 이익-위험 분석서 (`benefit-risk`)

- 필요 여부: 필수
- 근거 조항: Annex I 1, Annex II
- 앱에서 열기: `/doc/benefit-risk` (전용 상세 템플릿)
- 왜 쓰는가: 잔여 위험이 임상적 이익으로 정당화되는지 보여야 시판이 허용된다. '위험을 감수할 가치가 있는가'에 대한 규제적 답을 문서화한다.
- 작성 전 준비물: 위험관리 파일·성능평가 결과; 임상적 이익 근거(문헌·데이터)
- 알아야 할 것: 임상적 이익의 정량/정성 근거; 잔여 위험의 종류와 수준; 이익이 위험을 능가한다는 판단 논리
- 섹션 순서:
  1. 1. 이익 요약
  2. 2. 잔여위험 요약
  3. 3. 이익-위험 비교 결론
  4. 4. 시판 후 업데이트 계획

### 안정성 시험 계획·보고서 (`stability-study`)

- 필요 여부: 필수 — 표시 유효기간·운송 안정성 입증.
- 근거 조항: Annex II 6.2, Annex XIII
- 앱에서 열기: `/doc/stability-study` (기본 템플릿)
- 왜 쓰는가: 표시된 유효기간·보관조건에서 성능이 유지됨을 입증하지 못하면 사용 시점의 결과를 신뢰할 수 없다. 유통·사용 전 구간의 신뢰성을 보장한다.
- 작성 전 준비물: 실시간·가속 안정성 시험 데이터; 운송(수송) 안정성 시험 결과; 보관조건·유효기간 설정 근거
- 알아야 할 것: 실시간 vs 가속 안정성의 차이와 한계; 유효기간·개봉 후 사용기간 설정 방법; 운송(수송) 조건 시험 요건
- 섹션 순서:
  1. 1. 목적 · 적용 범위
  2. 2. 실험 설계
  3. 3. 근거 · 참조
  4. 4. 검토 · 승인
  5. 5. 결과
  6. 6. 결론 · 라벨 반영

### 생체적합성 평가 (ISO 10993) (`biocompatibility`)

- 필요 여부: 해당 시 — 환자·사용자 접촉부가 있을 때.
- 근거 조항: ISO 10993, Annex I
- 앱에서 열기: `/doc/biocompatibility` (기본 템플릿)
- 왜 쓰는가: 환자·사용자와 접촉하는 재질이 생물학적으로 안전한지 입증해 유해반응 위험을 차단한다.
- 작성 전 준비물: 접촉부·재질 목록; 세포독성 등 생물학적 시험 데이터; 화학적 특성평가
- 알아야 할 것: 접촉 분류·기간(ISO 10993-1); 필요 시험 항목 선정; 화학적 특성평가 활용
- 섹션 순서:
  1. 1. 목적 · 적용 범위
  2. 2. 핵심 내용
  3. 3. 근거 · 참조
  4. 4. 검토 · 승인

- 섹션 순서:
  1. 1. 목적 · 적용 범위

  6. 6. 아키텍처 · 상세 설계 · SOUP (§5.3–5.4)

## 위험·사용적합성
근거: ISO 14971, IEC 62366

### 위험관리 계획 + GSPR↔위험 추적표 (`risk-management-plan`)

- 필요 여부: 필수
- 근거 조항: ISO 14971:2019, Annex I
- 앱에서 열기: `/doc/risk-management-plan` (전용 상세 템플릿)
- 왜 쓰는가: IVDR Annex I GSPR 8조는 위험관리가 제품 수명 전주기에 걸쳐 수행돼야 한다고 규정한다. 위험이 없다고 주장하는 것은 NB가 수용하지 않으며, 잔여위험의 수용 근거가 명확해야 한다.
- 작성 전 준비물: 의도된 목적 정의서 — 사용자·환경 확정 필요; 기기 설명서·사양 (Annex II 1.1); FMEA 또는 FTA 분석 결과 (초안); 유사 기기 불만·바이질런스 데이터 (있을 경우)
- 알아야 할 것: ISO 14971:2019 — 위험관리 프로세스 전체 구조 (7단계); 위해요인(Hazard) vs 위험상황(Hazardous Situation) vs 위해(Harm) 구분; 발생가능성(P) × 심각도(S) 위험 수용 기준 행렬 설계; IVD 특유 위해요인: 위양성·위음성 결과가 치료 결정에 미치는 영향; GSPR 8조~18조 각 조항과 위험의 연결 구조; IEC 62366 (사용적합성) — 자가검사·근접검사 제품에 필수 연계
- 섹션 순서:
  1. 1. 위험관리 계획 (ISO 14971 Clause 4.4)
  2. 2. 위험 분석 — IVD 특유 위해요인
  3. 3. GSPR↔위험↔성능 추적표
  4. 4. 사용적합성 연계 (IEC 62366 — 자가검사·근접검사 해당 시)

### FMEA (고장모드 영향분석) (`fmea`)

- 필요 여부: 해당 시 — ISO 14971 위험분석의 상향식 기법 — 설계(dFMEA)·공정(pFMEA)·사용(uFMEA)으로 적용. FMEA는 의무가 아니나 실무 표준.
- 근거 조항: ISO 14971:2019, IEC 60812
- 앱에서 열기: `/doc/fmea` (기본 템플릿)
- 왜 쓰는가: FMEA는 부품·공정·사용 단계의 잠재 고장이 어떤 위해로 이어지는지 짚는 상향식(bottom-up) 분석이다. '무엇이 어떻게 잘못될 수 있는가'를 빠짐없이 드러내 통제수단을 설계하고, ISO 14971 위험관리 파일을 구체적 근거로 뒷받침하기 위함이다.
- 작성 전 준비물: 위험관리 계획·기기 기능/부품 목록; 고장모드·원인·영향 후보 목록; 심각도·발생도·검출도 평가 척도(RPN 기준)
- 알아야 할 것: dFMEA·pFMEA·uFMEA의 구분과 적용 범위; 심각도(S)·발생도(O)·검출도(D)와 RPN 산정 방법; FMEA 결과를 ISO 14971 위험통제·추적표로 연결하는 방법
- 섹션 순서:
  1. 1. 목적 · 적용 범위
  2. 2. 핵심 내용
  3. 3. 근거 · 참조
  4. 4. 검토 · 승인
